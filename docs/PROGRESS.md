## 1단계. 천문 계산 엔진

- **테스트 결과**: 전부 통과. 대상별 최대 오차 (굴절 없이):

  | 대상 | 최대 오차 |
  | --- | --- |
  | 별(고도 5° 이상, 275건) | 0.0060° |
  | 해 | 0.0005° |
  | 달 | 0.0014° |
  | 수성 / 금성 / 화성 | 0.0014° / 0.0034° / 0.0012° |
  | 목성 / 토성 | 0.0014° / 0.0046° |
  | 달 빛난 비율 | 0.003%p |

- **고유운동 판단**: 반영함. HYG 좌표는 2000년 기준이라, 빠른 별(예: 바너드 별, 아크투루스)은 26년 사이 수십 각초~수 분 움직인다. 앱을 쓰는 몇 년 동안은 차이가 작으므로 **빌드할 때 2026.5년 기준으로 한 번만** 적용했다(계산 비용 0). 정답지(Skyfield)도 고유운동을 넣어 계산하므로 테스트에서 일치 확인.
- **Stellarium 비교 제안**: docs/ACCURACY.md의 3개 장면(베텔게우스·리겔·시리우스 / 알타이르·안타레스·토성 / 달·카펠라·알데바란).
- **남은 문제**: 없음.

## 2단계. 별 데이터 + 첫 밤하늘 + 둘러보기

- **한 일**: HYG v4.2 → `stars.bin` (6.5등급까지 8,920개, **217.8KB**). 별은 Points 하나(그리기 1번), 등급→크기·밝기, B-V→색, 가운데 밝고 가장자리 부드러운 모양, 지평선 근처 흐려짐. 땅·지평선 동서남북. 드래그·핀치·휠, 관성, 천정 너머로 안 뒤집힘.
- **테스트 결과**: 베텔게우스·리겔·시리우스의 계산 위치 픽셀이 밝은지, 다른 시각 위치는 어두운지(1픽셀 어긋남도 잡음), 드래그 방향, 시야각 20~100° 제한, 같은 URL=같은 화면 — 데스크톱·모바일 통과.
- **스크린샷 확인** (`docs/screenshots/stage-2/`): 오리온자리 모양, 벨트 세 별, 베텔게우스 주황·리겔 청백색이 분명함. 처음엔 별이 너무 작고 선이 진해서 별 크기·밝기를 키우고 선을 옅게 조정함.
- **Stellarium 비교 URL**: docs/ACCURACY.md 장면 1·2.

## 3단계. 별자리 선·한글 이름·별 터치

- **한 일**: d3-celestial 별자리 선을 HYG 별에 맞춤(꼭짓점 최대 0.0211°). 88개 별자리 한글 이름 + 밝은 별 80개 이름. 이름표는 겹치지 않게 배치(중요한 것 우선). 탭: 손가락 크기(44px) 반경, 비슷하면 밝은 별 우선, 드래그와 구분. 정보 카드(이름·별자리·밝기·거리), 고른 별에 고리.
- **테스트 결과**: 통과. 이번에 모바일에서 "리겔 옆 18px을 누르면 리겔" 테스트가 실패해서(근처 4등급 별 에리다누스자리 λ가 골라짐) 밝기 가중치를 0.1 → 0.2로 올려 해결.
- **스크린샷 확인** (`stage-3/`): 카드가 아래쪽에 뜨고 하늘을 가리지 않음, 이름표 안 겹침.
- **확인 못 한 이름**: 별자리 이름은 한국어 위키백과 목록과 대조함. **Her는 "헤르쿨레스자리"**로 적었는데 위키백과는 "허큘리스자리" — 한국천문학회 최신 표기를 사람이 확인 필요. 밝은 별 이름은 널리 쓰이는 음역이라 공식 출처와 1:1 대조는 안 함.

## 4단계. 달·행성·해 + 하늘색

- **한 일**: 달(실제 크기 0.5°, 위상은 셰이더 — 빛나는 쪽이 해를 향함), 행성 5개(밝기로 크기, 한글 이름), 해. 해 고도에 따른 하늘색(낮·해 질 녘·시민/항해/천문 박명·밤), 낮엔 별 안 보임. "오늘 밤으로 보기"(해가 -18°가 되는 때, 안 되면 -12/-6/가장 낮을 때) + "지금으로 돌아가기".
- **테스트 결과**: 통과 (하늘 밝기 순서, 버튼 시각 = 따로 계산한 -18° 시각 1초 이내 등).
- **스크린샷 확인** (`stage-4/`): 낮 파란 하늘 → 해 질 녘 주황 → 박명 → 밤 남색 순서 자연스러움. 달 확대 3장(보름·초승·하현) 모양과 빛나는 방향 맞음(초승: 해가 진 서쪽 아래, 하현: 해가 뜰 동쪽 아래).
- **남은 문제**: 확대한 달의 "달" 이름표가 달 아래쪽에 살짝 겹침 (작은 문제, 나중에).

## 5단계. 폰 방향 따라가기

- **한 일**: 시작 화면(버튼 하나 + 위치 안내 한 줄). 버튼을 누른 그 순간 방향 허용을 **먼저**(await 없이) 요청 → 이어서 위치. 센서 → 회전값(쿠오터니언)으로 카메라 방향, 손떨림 줄이기(0.12초), 안드로이드는 `deviceorientationabsolute`, 아이폰은 `webkitCompassHeading`으로 방위 맞춤(폰을 거의 세워서 위쪽 방위가 불안정할 땐 마지막 값 유지). 좌우 드래그로 "나침반 보정"(저장됨, 설정에서 초기화). 자기 편각 보정 옵션(한국 약 -8.5°, 기본 켬). 거부·센서 없음 → 서울 기준 드래그 모드 + 안내.
- **테스트 결과**: 가짜 센서 값으로 방향 일치(0.5° 이내), 편각, 아이폰 방식, 보정 저장, 모드 전환 — 통과. 이번에 요즘 크롬에도 `requestPermission`이 생겨서 테스트에서 "허용"을 흉내 내도록 고침.
- **확인 못 한 것(추측)**: 아이폰 `webkitCompassHeading`이 자기 북쪽인지 진짜 북쪽인지 문서로 확실히 확인하지 못함. 그래서 편각 보정을 켜고 끌 수 있게 했다 → 실측 필요.

### 아이폰 실기 테스트 체크리스트 (밖에서, 맑은 밤)

1. 배포 주소를 **사파리**로 열고 "하늘 보기 시작" → 방향 허용 → 위치 허용. 화면 위에 "내 위치"가 뜨는지.
2. 폰을 들고 천천히 한 바퀴 돌기: 화면이 끊기지 않고 따라오는지, 떨리지 않는지.
3. **달이나 밝은 행성(목성·금성)에 폰을 겨누기**: 화면 가운데 근처에 같은 천체가 있는지. 좌우로 몇 도 어긋나는지 눈대중으로 적기.
4. 설정 → "진짜 북쪽으로 보정"을 끄고 다시 3번. 켰을 때와 껐을 때 중 어느 쪽이 더 맞는지 → 알려 주면 기본값을 정함.
5. 어긋나면 좌우로 끌어서 맞추고, 탭을 닫았다 다시 열어도 보정이 남는지.
6. 폰을 머리 위(천정)로 들었을 때 화면이 빙빙 돌지 않는지.
7. 가로로 돌렸을 때도 방향이 맞는지.
8. 문제가 있으면 주소 끝에 `?debug=1`을 붙여 열고 화면을 캡처해서 보내기 (센서 값·나침반 정확도·오류가 보임).
9. 방향 허용을 일부러 "허용 안 함" → 드래그 모드로 열리는지, 다시 켜는 방법(탭 닫고 새로 열기)이 실제로 되는지.

## 6단계. 은하수·반짝임·지평선 빛

- **한 일**: Gaia 전천 이미지를 은하 좌표 → 적도 좌표로 바꾸고 밝은 별을 지우고 흐리게(1024x512 WebP **6.2KB**). 하늘 셰이더에서 밤에만 옅게. 별 반짝임(지평선 근처일수록 강하게), 해 질 녘 해 쪽 지평선의 노을빛.
- **테스트 결과**: 은하수 그림이 알맞은 위치(데네브·알타이르·궁수자리 쪽 밝고 북두칠성 쪽 어두움), 밤에만·달이 밝으면 약해짐 — 통과.
- **스크린샷 확인** (`stage-6/`): 여름 은하수(궁수자리~독수리자리)가 "있는 듯 없는 듯" 보이고 별을 가리지 않음. 겨울 은하수는 더 희미함(실제와 같음). 끈 화면과 비교해 과하지 않음.

## 7단계. 별똥별·오로라 꿈 모드·설정

- **한 일**: 별똥별(평균 28초에 하나, 밤에만, seed로 고정), 오로라 꿈 모드(북쪽 낮은 하늘 초록 커튼, "한국에선 거의 볼 수 없는 상상 모드" 표시, 기본 꺼짐), 설정 패널(화면 아래쪽, 7개 토글 + 도시 10곳 + 나침반 보정 초기화 + 편각 보정, 저장됨), `?aurora=1`.
- **테스트 결과**: 통과. 스크린샷용으로 별똥별이 어디 있는지 앱에 물어보는 값(`meteorAzAlt`)을 추가해 별똥별 방향을 찍게 함.
- **스크린샷 확인** (`stage-7/`): 오로라는 북쪽 지평선 위 초록 띠로 보기 좋음. 별똥별은 가는 꼬리가 자연스러움. 설정 패널은 한 손으로 닿는 아래쪽.

## 8단계. 성능과 안정성

- **한 일**: 화질 자동 조절(느리면 해상도 배율 2 → 1.5 → 1 → 은하수 끔), 가만히 있으면 초당 약 20번만 그림, 탭을 숨기면 멈춤, WebGL 끊기면 다시 시도, 별 데이터를 먼저·은하수는 나중에. WebGL 없음·데이터 실패 → 흰 화면 대신 안내 + 다시 시도. localStorage가 막혀도 동작. 카톡 인앱 브라우저 감지 시 "다른 브라우저로 열기" 안내. `?debug=1` 패널, `?debug=table` 표. 빌드 후 크기 검사(`npm run size`, CI에 포함).
- **테스트 결과**: 통과. 첫 화면 372.5KB / 전체 1007KB.
- **스크린샷 확인** (`stage-8/`): 디버그 패널 글자가 읽힘, WebGL 안내 화면이 어두운 배경에 버튼과 함께 뜸.
- **확인 못 한 것**: 실제 아이폰의 FPS·발열, 카톡 인앱 브라우저에서 센서·위치 허용이 되는지.
